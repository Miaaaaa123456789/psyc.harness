# 经营协同看板公开脱敏版

演示的是界面，不是虚构的数据。营收金额、业务量、源表分数保持真实，员工姓名改为匿名编号。用户已明确要求在公开个人仓库保留真实汇总值。

## 数据范围

- 营收日报：2026-10-01—2026-10-15，累计1,286,032.05元。逐日金额不缩放、不扰动。
- 医生、护理、心理、客服、营销分别使用快照中明确标注的区间。不同周期不强行合并。
- 医生金额为已出院个人归属业绩，不是全院营业额。
- 真实姓名、患者级明细、员工姓名映射、在线表访问地址、cookies、密码和令牌不包含在此目录。
- 匿名员工ID与当前源表分数一一对应。后续更新必须按ID合并，禁止按当前名次重新编号。
- WPS在线表本轮完整刷新尚未完成。不得把保留旧快照写成同步成功。

## 文件结构

`public-snapshot.js` 是允许公开的真实脱敏汇总。
`data-model.js` 统一计算金额、时间、同长同期和源表排名。
`data-adapter.js` 接收后续私有API，默认读取脱敏汇总，不向GitHub写运行数据。
`app.js` 实现总览、营销、部门诊断、排名、数据状态和抽屉。
`ui.css` 复用当前已发布看板的视觉样式。`shell.css` 只提供独立运行所需外壳。

这是独立可运行的脱敏呈现层导出，不把旧HTML内嵌的原始叙述、患者数据或姓名复制到公开目录。它不覆盖私有Site，也不删除仓库现有旧模块。

## 运行与验证

直接打开`index.html`即可读取已打包的脱敏快照。若需请求API，请使用标准静态HTTP服务器。

```sh
node tests/metrics.test.cjs
```

无需运行时依赖、CDN、云OCR或远程大模型。AI辅助分析目前是确定性指标核算与待核假设，不是远程模型诊断。

## 后端注入契约

在页面加载`data-adapter.js`前注入运行配置。地址与认证只在院内部署配置，不提交到公开仓库。

```js
window.OPS_DASHBOARD_CONFIG = {
  snapshotUrl: '/api/dashboard/snapshot',
  uploadUrl: '/api/dashboard/revenue-import',
  confirmUrl: '/api/dashboard/revenue-import/confirm',
  pollMs: 60000
};
```

快照结构与`public-snapshot.js`一致。API返回`mode: 'private-runtime'`，所有员工包含稳定的`id`。同源请求沿用受保护会话，不在前端保存令牌。跨源需后端自行提供合适的认证和CORS，不能通过公开前端内嵌密钥解决。

每次拉到有效快照后派发`ops:snapshot-updated`，主页、营销与部门组件重算。读取失败保留上次有效数据并显示失败状态。

图片/表格上传API必须先返回`{importId,rows}`供预览，用户确认后才入库。未配置后端时明确报告不能识别，不模拟成功。JSON导入仅更新页面内存，不宣称跨设备保存。

## 计算约束

1. 金额单位元，展示万元时才舍入。真实0与null区分。
2. 月时间进度按数据截止日计算，不按页面打开日计算。
3. 进行中周只比较上一周同长且日期连续的前缀，缺日报不显示确定环比。
4. 护理和心理排名使用源表提供的综合分，不重新发明权重。出勤天数只作样本提示。
5. 没有患者级共同ID时，不把客服到院、管家住院转介和营收串成同队列漏斗。
6. 单日异常评分保留源值和待核提示，不擅自删除后重新排名。
7. 没有成本、投入、回款与归因记录时，利润率、ROI和回款率显示待补。

公开仓库意味着任何人都可读取这些真实汇总金额。若不再希望公开，应使用私有仓库和院内API；仅删除最新文件不会自动清除Git历史。
